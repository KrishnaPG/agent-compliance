## Part B: Claude Code hooks (docs fetched 2026-11-25)
Sources: https://code.claude.com/docs/en/hooks (HOOKS), /sub-agents (SUB), /worktrees (WT).

1. Events inside subagents. HOOKS "Hook locations" section: hooks from settings files, managed policy and plugins also run inside subagents; PreToolUse and PostToolUse fire the same configured hooks as in the main conversation, with agent_id and agent_type in input. SUB "Hooks" confirms. SubagentStart and SubagentStop fire in the parent session around each subagent (HOOKS "SubagentStart", "SubagentStop"; matcher is agent type; plugin agents are plugin-scoped, e.g. `^agent-compliance:harness-builder$`). SubagentStop is the subagent's end-of-turn event (a Stop hook defined in subagent frontmatter is its end hook). SessionStart/UserPromptSubmit are session-level: UserPromptSubmit also fires when a background subagent reports back to the session (HOOKS "UserPromptSubmit"); SessionStart is not documented as firing per subagent: use SubagentStart. (Stop in a subagent: docs do not state it separately; treat SubagentStop as the one.)
2. Blocking (HOOKS "Exit code 2 behavior per event", "Exit code output"). Can block: PreToolUse (blocks the call), UserPromptSubmit, Stop (forces continue), SubagentStop (prevents the subagent stopping), PostToolBatch, TaskCompleted, PreCompact, WorktreeCreate and others. Cannot block: PostToolUse (stderr shown to Claude, tool already ran), SubagentStart and SessionStart (stderr to user only; Claude does not see it). Mechanism: exit 2 with stderr as the reason, or JSON (PreToolUse `permissionDecision: "deny"` + `permissionDecisionReason`; Stop/SubagentStop `decision: "block"` + reason). Agent sees the stderr or reason as the tool-call refusal; on Stop/SubagentStop the reason arrives as feedback and the turn continues.
3. Adding context (HOOKS "Add context for Claude"). `hookSpecificOutput.additionalContext` works on SessionStart, SubagentStart (placed before the subagent's first prompt), UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStop. Wrapped in a system reminder; multiple hooks all delivered. Cap: additionalContext, systemMessage, initialUserMessage and plain stdout are each capped at 10,000 characters; beyond that the text is written to a file in the session dir and Claude gets the path plus a preview of the first 2,000 characters. SubagentStart re-injects only when the subagent's context does not already hold it (same section).
4. Telling subagent from main (HOOKS "Common input fields"): `agent_id` and `agent_type` present when the hook fires inside a subagent (agent_type also set under `--agent`; subagent type wins). cwd is the hook's current working directory, so a worktree subagent shows its worktree path in `cwd`; there is no dedicated "worktree" field in common input (not found). SubagentStop adds agent_transcript_path and last_assistant_message.
5. Project .claude/settings.json in worktree subagents. SUB "Hooks" and HOOKS "Hook locations": settings-file hooks apply inside subagents. A worktree is a checkout of the repo, so tracked .claude/settings.json is present; untracked files (settings.local.json, .env) are NOT, unless listed in `.worktreeinclude` (WT "Copy gitignored files into worktrees"). Hook paths: `${CLAUDE_PROJECT_DIR}` stays at the session root, it does not follow the worktree (WT note "Hook paths don't follow the worktree"), so a hook script must read the worktree from `cwd`. Plugin subagents ignore `hooks`, `mcpServers`, `permissionMode` frontmatter (SUB "Plugin subagents note"); ship hooks in the plugin's hooks/hooks.json instead (apply whenever the plugin is enabled, including in subagents).
6. Token cost. Hook stdout/additionalContext becomes input tokens each time it is injected (system reminder next to the tool result for tool events; so a PreToolUse injection repeats per call and is not cached across the conversation as a one-off). Cap is characters (10,000 ~ 2,500 tokens per string per event). Hooks that exit 0 with no output cost nothing in tokens; blocks cost the stderr text only. Subagents also load CLAUDE.md and AGENTS.md at start (SUB "What loads at startup") except Explore, Plan, web-fetch; so every spawned non-Explore subagent pays AGENTS.md + global CLAUDE.md tokens. SubagentStart injection is once per subagent, cheaper than PreToolUse injection.

## Takeaways for design
- Reuse bh-brief/work-packet and the measurer; they cover stage 2 for harness items. Gaps to design: per-item ATDD authoring by a non-builder before the build (protected paths + holdout exist to receive it), epic-level design trigger, and all just-in-time hooks (none shipped).
- Cheapest JIT channel: plugin hooks/hooks.json with SubagentStart additionalContext (once per subagent, keyed by agent_type, packet <10k chars) and PreToolUse deny with a reason for structure rules; PostToolUse cannot block.
