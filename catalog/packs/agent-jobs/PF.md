# Agent jobs pack, PF rules

Pack `agent-jobs` for base catalog 1.4.0. Scope: designs in which a program or harness starts AI agent jobs (an LLM with tools, run by the program without a person in the conversation): no agent in a mechanical path, minimal context, agent definitions, stable prompt prefix, caps and convergence, structured results. Loaded only when the project overlay names this pack. Each row is the whole rule.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| AJ-02 | Each agent job starts with only what its job uses: its own instructions, the tools it calls (least privilege, ID-11) and the files it reads; passing large inputs by path is PF-05's. Instructions, memory, plugins, skills and tool servers the job does not use (the host's user-wide instructions and memory included) are not loaded (the host's bare or minimal mode, with the job's own definition, tools and servers passed explicitly). What a job loaded is judged from its own start or usage record, not from its definition. NA where the design starts no agent job. | Anthropic, "Effective context engineering for AI agents" (2025), https://www.anthropic.com/research/effective-context-engineering-for-ai-agents: the smallest possible set of high-signal tokens; Claude Code docs, "Run Claude Code programmatically", https://code.claude.com/docs/en/headless: `--bare` skips auto-discovery of CLAUDE.md, auto memory, plugins, skills and MCP servers; `--agents`, `--mcp-config`, `--settings` load only what is named | For one agent job, which instructions, memory, tools, servers or files does its start record show loaded that the job does not use? |
| AJ-04 | Agent jobs of one kind start from an identical prefix: the same tools, system instructions and fixed context, in that order, with the job-specific data (paths, ids, the item, the diff) after it; nothing that varies per job (a timestamp, a run id, a file or tool order that is not fixed) appears in the prefix, so the host's prompt cache can serve it. This adds no cache of ours (PF-09); the cache-read share is read from the jobs' usage records, never assumed, since a cache entry expires (5 minutes by default on the Anthropic API). NA where no kind of agent job runs more than once. | Anthropic API docs, "Prompt caching", https://platform.claude.com/docs/en/build-with-claude/prompt-caching: the cached prefix is tools, system, then messages, in that order; static content goes first; a hit needs 100 percent identical prompt segments; default lifetime 5 minutes | For one job kind, what differs between two jobs' prompts before their job-specific data, and what cache-read share do their usage records show? |
| AJ-05 | Every agent job runs under a turn limit the host enforces (declared in the job kind's agent definition, AJ-03) and a spend cap the program sets from configuration, besides its deadline (RL-06); reaching either ends the job failed and reported as failed (RL-17). The CLI's spend cap is a client-side estimate and only a backstop; a budget read from the metering owner is PF-14's. NA where the design starts no agent job. | Claude Code docs, "Subagents", https://code.claude.com/docs/en/sub-agents: `maxTurns` frontmatter field of an agent definition; CLI reference, https://code.claude.com/docs/en/cli-reference: `--max-budget-usd` (spend cap for a non-interactive run). Convention: every unattended job is bounded (RL-06) | What turn limit and spend cap does each job kind run under, where is each set, and what happens when a job reaches one? |
| AJ-07 | A loop of agent rounds (build then measure, review then fix) has a stated round bound and records each round's measured numbers; it stops, reported as not converged, when a round moved none of them or at the round bound (PF-06), and never starts another round on unchanged inputs. NA where the design runs no loop of agent rounds. | Convention: an agent loop stops when a round moves no measured number; PF-06 (no unbounded retry) applied to agent rounds | What is the loop's round bound, what ends it, and in a recorded run did a round follow one that moved no number? |
