# React web frontend pack, UI rules

Pack `react` for base catalog 1.0.0. Scope: request data, push channels, render flow, modularity. Loaded only when the project overlay names this pack. Each row is the whole rule.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| RX-01 | The request library owns request-and-response data: calls, cacheable reads, retries, invalidation, mutation status. It is never the owner or event bus of a long-lived push channel (WebSocket, server-sent events, data channel, worker stream). Query keys come from a typed factory and invalidation is targeted. | TanStack Query documentation; React documentation | Does a UI design route a push channel through the request library, or invalidate broadly? |
| RX-02 | A long-lived push channel is owned by a stream or session adapter with explicit start, stop and subscribe, cancellation, bounded buffering, back pressure, timeout, retry, reconnect and close, cleaning up exactly what it acquired. No component or hook owns a transport read loop; no unbounded queue; no per-frame React state setter. | WHATWG Streams (back pressure); React documentation (effects and cleanup) | What bounds the channel's buffer, and what reconnects and cleans it up? |
| RX-03 | External frames are validated exactly once, at the transport boundary, and decoded into typed UI intents through a registry; components never switch on raw backend payloads. | Parse-at-the-boundary practice | Where is each frame validated, and does any component read a raw payload? |
| RX-04 | A multiplexed channel separates transport identity from consumer identity: the session owns the connection; each panel or view subscribes through a typed handle and owns its interest, cursor, watermark, schema version and cleanup. | Multiplexed transport practice (WebTransport, WebSocket subprotocols) | Does any consumer read the raw channel instead of its own subscription? |
| RX-05 | A snapshot-then-tail flow takes the immutable snapshot by request and the live tail by the adapter; snapshot and live reconciliation, cursor-too-old, schema change, governance change and resnapshot are each stated. | Event-sourced read-model practice (snapshot plus tail) | What happens when the tail's cursor is too old or the schema changes mid-stream? |
| RX-06 | High-frequency state (packets, decoder buffers, pointer, playback, viewer internals) stays out of the React render flow; only coarse fields (status, version, cursor, watermark, unread count, last error) drive render. A snapshot of a broad or root store is forbidden; client state changes only through named store actions. | React documentation (render purity; external stores) | Which state updates per frame, and does it reach render? |
| RX-07 | Files stay below 400 lines and components and functions below 50. Components do not transform data and contain no effect hook (effects, subscriptions and viewer integration live in custom hooks or adapters that clean up deterministically and handle cancellation); route, panel and event-based components load by dynamic import through a registry; mature open-source packages are preferred over custom UI plumbing. | React documentation; component-size practice | Does any component compute data, hold an effect, or exceed the size bounds? |
