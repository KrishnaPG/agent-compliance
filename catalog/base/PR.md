# PR: Process

Base catalog 1.0.0. Scope: defect records, independent review, forward-only history, tests kept strict. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| PR-01 | A defect of any size gets a record with its root cause and a test that reproduces or guards it; its fix references the record. The record closes only when that test passes on the fixed product, and a later failure reopens it. | Google SRE book ch. 15 (postmortems) | What does the artifact say to do when a defect is found during the work, and when does its record close? |
| PR-02 | No rule requires a test. One is written only for what no dashboard, log, platform status, check, release gate or release smoke would show: racy or edge-case decision logic, absence invariants, money and entitlement arithmetic, transformation programs on fixtures, cross-service schemas, the order of irreversible steps. Never a test that searches source text or repeats an outcome a release shows. | Convention: tests for unseen behaviour only | What does each proposed test catch that nothing else shows? |
| PR-03 | Pushed history is never rewritten and the main branch is never force-pushed; a commit refused after it was pushed is corrected by a later commit that names it. | Convention: shared history is never rewritten | Does any step rewrite or force-push history? |
| PR-04 | The review is by a reviewer who did not write the artifact and shares no context with its author, given the artifact without the author's reasoning; it names a location and a fix for each finding. | Convention: independent artifact review | Who reviews, and what is the reviewer given? |
| PR-05 | The owner's validator (server dry-run, chart template with merged values, rule checker, template render) runs on changed files before commit and is named in the commit. | Convention: owner validator before commit | Which validator covers each changed file? |
| PR-06 | People's and agents' own waits follow RL-08: no sleep or poll loop in a shell; a wait is on the producer's event or a background task's completion. | Convention: wait on events, not loops | Does any instruction tell a person or agent to sleep or poll? |
| PR-07 | The standards win over a brief or an older artifact. A gate's refusal means the change broke a rule and is answered by a design step back, never a bypass. | Convention: gate refusal means redesign | What does the process do when a gate refuses? |
| PR-08 | No existing acceptance test is changed, loosened, skipped, re-timed or re-seeded to make it pass; a failing acceptance test is a product defect. Exception: the native owner's source proves no correct product can pass it as written, or a later approved decision settles which of two contradicting tests is stale; then only that defect is corrected, every assertion stays as strict, and the proof is recorded on the defect. | Convention: acceptance tests never weakened | Does the work edit an existing acceptance test, and under which exception? |
| PR-09 | Every confirmed review or audit finding is recorded on its tracker in the same turn it is found; none stays in prose. | Convention: findings tracked as issues, not prose | Where does each finding go, and when? |
| PR-10 | Only decisions that are the project owner's to make are escalated (a conflict between approved documents, a new owner, a wider privilege, retention, scope), each named as such. Anything else is decided by the standard and recorded. An escalation never stops the work. | Convention: decision rights (who decides, who is consulted) | Is each open question the owner's to decide, and does work continue around it? |
| PR-11 | A place that two fixes have already rewritten since its last verified release is redesigned at its cause, never patched a third time. | Google SRE book ch. 15 (postmortems: root causes) | Does the work patch a place already fixed twice? |
| PR-12 | An end-to-end test derives from one acceptance criterion of a journey, names it and asserts only that criterion's outcome; a test with no criterion is deleted or its criterion is added to the journey. | Convention: one acceptance criterion per end-to-end test | Does each proposed end-to-end test name its criterion? |
| PR-13 | An agent session never runs a command that discards uncommitted or unpushed work (stash, hard reset, path checkout, clean, forced push); work is committed to a branch or backed up first. | Convention: no discarding of uncommitted work | Does any step discard uncommitted or unpushed work? |
