# PF: Performance and footprint

Base catalog 1.1.0. Scope: budgets with numbers, dirty-only work, parallelism, zero-copy, bounded settings. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| PF-01 | Each affected hot stage names its latency, throughput, concurrency, cost and copy budgets as numbers, with the measured value and where it is read, or states that none is measured; it names bounded buffering, back pressure and each avoidable copy or serialization point. | Measure-before-optimizing practice; Google SRE book ch. 6 (latency, traffic, saturation) | For each target: its number, the measurement, the reading location? |
| PF-02 | Only dirty nodes run: a node whose content inputs are unchanged is skipped. Its memo is keyed on the content it derives from and its target's identity, never on a commit or ref, and every output a later node reads is declared as generated. | Convention: content-keyed memoization | What decides that each node runs, and does a new commit alone re-run it? |
| PF-03 | Independent nodes run in bounded parallelism; only effects wait, each only for what it consumes; no serial edge exists that no shared object needs. | Convention: bounded parallel independent steps | Which edges of the graph are serial, and what shared object justifies each? |
| PF-04 | Owner work runs in one owner process (one import, one migrate); never a process or container per record. | Convention: one owner process per bulk step | How many owner processes does a bulk step start? |
| PF-05 | Large payloads move by immutable reference or direct range transfer, never copied through the control plane or an application service. `NA` where the artifact has no data path. | Enterprise Integration Patterns: Claim Check | Does any byte stream pass through a step that only needs its reference? |
| PF-06 | Queue, batch, retry, timeout, payload and fan-out settings are bounded. | Convention: every queue, batch, retry and timeout bounded | Which of these has no stated bound? |
| PF-07 | Concurrency is limited only where order matters, per aggregate partition. A flow-wide limit never serializes independent tenants or installations past their deadline. | Convention: per-partition concurrency limit | Does one tenant's or installation's work wait behind another's? |
| PF-08 | When a time gate is missed, the lever is pipelining chosen by benchmark (a stated number of runs each, wall time and CPU); removing a check is never the lever, and no timeout or interval is set that lengthens a release. | Measure-before-optimizing practice; Google SRE book ch. 6 (latency, traffic, saturation) | How does the design get faster, and does it drop a check to do so? |
| PF-09 | Measure before optimizing: a cache, batch or parallel path is added only for a concrete measured requirement. | Measure-before-optimizing practice; Google SRE book ch. 6 (latency, traffic, saturation) | Which measurement justifies each cache, batch or parallel path? |
| PF-10 | A changed program (flow, expression, route, engine configuration) has run on its pinned engine image with production-size input, within the engine's documented limits, before it lands; validation alone is not a run. The change states the measured time and memory of the run before and after it. | Convention: run changed program at production size | On which input size was each changed program run? |
| PF-11 | Every list read is paged to its end or checked for truncation; a limited read never passes as complete. | Release It! 2nd ed. Unbounded Result Sets | Which reads can be cut by a page limit, and what detects it? |
| PF-12 | A release that changes nothing does near-zero work and meets a stated time ceiling; every release that is not from scratch has a stated ceiling too. | Convention: incremental, idempotent delivery (a no-op run does near-zero work) | What still runs when nothing changed, and does it meet the stated ceiling? |
| PF-13 | The platform's footprint with zero customers has a stated ceiling. No always-on per-tenant copy of a shared function is added. | Convention: capacity planning with a stated idle-footprint budget | What does the design add to the idle footprint, and is any of it per tenant? |
| PF-14 | Each cost or usage budget has an alert before its ceiling and a declared action at it (refuse new work, shed, or escalate to the project owner); spend is read from the owner that meters it, never estimated from telemetry. | Convention: budget alert and action (FinOps Framework: Budgeting) | What alerts before each ceiling, and what happens at it? |
| PF-15 | An artifact (image, bundle, model, archive) crosses the network at most once per consumer node: shared layers or chunks are referenced by digest and reused, no whole-artifact archive is staged on the way, no host-path cache is relied on, and parallel transfers run within a stated bound. NA where nothing is distributed. | Convention: content-addressed layer reuse | How many times is each artifact transferred or copied on its way to a node? |
