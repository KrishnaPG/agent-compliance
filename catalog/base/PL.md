# PL: Platform reconciliation and release

Base catalog 1.0.0. Scope: declared and pulled desired state, immutable releases, manual actions. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| PL-01 | An operator or break-glass action is one native call that keeps no orchestration state and polls nothing; the platform's access control decides who may run it; a destructive reset of an installation needs the installation's name typed as confirmation. | Convention: single-call operator action | Is each manual action one call, what authorizes it, and what does it confirm before destroying? |
| PL-02 | Desired state is declared, not scripted; stored versioned and immutable with its history; pulled by the platform's own agent, not pushed by hand; and continuously reconciled by that agent. The declared state holds only L1-L4 resources; run-time operations (L5) and durable results (L6) are never in it. | OpenGitOps v1.0.0 1, 2, 3, 4 | Is any desired state imperative, mutable in place, or pushed by hand? |
| PL-03 | Build, release and run are separate stages: a release is an immutable pinned commit with its digests, and a running host changes no code or artifact. A release run pins the pushed head at its start, works from its own isolated checkout of that commit to the end, refuses uncommitted deploy changes, and nothing edited, committed or pushed during the run changes what it executes or how a check judges it. | Twelve-Factor App V | Can the running system differ from its release without a new release? Can an edit, commit or push during a run change what that run executes? |
| PL-04 | A dependency is either required (a consumer's readiness waits on its health) or optional (no readiness, release or health check waits on it, and its absence degrades one named feature). Nothing a consumer needs to serve is declared optional. | Convention: no optional health-gated dependency | Which dependencies are optional, and does anything wait on them? |
