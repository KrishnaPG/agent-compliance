# ID: Identity and secrets

Base catalog 1.0.0. Scope: secret custody and transport, least privilege, rotation, revocation, tenant isolation of access. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| ID-01 | No secret appears in process arguments, logs or messages. A token is passed on standard input or by a file (registry auth by an auth file, the Receiver token on stdin). | NIST SP 800-53 Rev. 5 AC-6, IA-5 | Where does each secret travel, and is it ever an argument or printed? |
| ID-02 | A signing key is a cloud KMS asymmetric key and never lands on a host; no key file exists. The cluster holds only the public key. | NIST SP 800-53 Rev. 5 AC-6, IA-5 | Where does each private key live, and what can read it? |
| ID-03 | Every account, binding and principal is a declared resource of an IaC root with a named duty and a removal path when the duty ends; none is created or changed by hand. | NIST SP 800-53 Rev. 5 AC-2, CM-3 | For each new principal: who owns it, what declares it, what removes it? |
| ID-04 | Consumers pick up a re-issued credential at once, by event, never only after a periodic refresh. | NIST SP 800-53 Rev. 5 AC-6, IA-5 | After a rotation, what makes each consumer pick up the new value? |
| ID-05 | Revocation removes the credential at its consumer first, then its account or state. An account whose duty ended is disabled or removed. | NIST SP 800-53 Rev. 5 AC-2(3) | In which order is a credential removed, and what is left behind? |
| ID-06 | A read error is never treated as absence: a generated-once value is never regenerated or overwritten because its read failed. Creation is the owner's check-and-set (written create-if-missing behind a guard read). | NIST SP 800-53 Rev. 5 AC-6, IA-5 | What happens when the read of an existing secret fails? |
| ID-07 | Every adapter derives its scope from trusted identity, holds least privilege and short-lived credentials, fails closed when authorization cannot be decided, has a tenant-denial test, and exposes no raw backing store or provider secret. Web surfaces meet OWASP ASVS level 2. | NIST SP 800-53 Rev. 5 AC-6, IA-5 | What does each surface do when authorization cannot be decided, and where is its tenant-denial test? |
| ID-08 | Cross-tenant resolution returns the same unknown-or-unauthorized result in every case; it reveals no node count, owner, timing difference or object existence. | NIST SP 800-53 Rev. 5 AC-6, IA-5 | Can a caller in tenant A learn that an object of tenant B exists? |
| ID-09 | The ingress is the sole entry for backend, authentication, RPC and admin traffic. Public URLs come from the declared profile and trusted forwarding metadata; cross-origin access admits exact origins only. A development security exception is explicit and unavailable in production. | NIST SP 800-53 Rev. 5 AC-6, IA-5 | Does any service take traffic or identity other than through the ingress? |
| ID-10 | A secret reaches a workload only from the secret store, by a declared reference the platform resolves. None is written by hand or carried in a deployable artifact. When the store is unavailable, readers do not start; there is no second custody. | NIST SP 800-53 Rev. 5 SC-12, SC-28 | By which path does each secret reach its consumer, and what starts when the store is down? |
| ID-11 | Each duty (plan, apply, release, read) has its own identity holding the least its steps need. Each automated step runs with a short-lived credential of its own duty; people hold no standing deployment roles. | NIST SP 800-53 Rev. 5 AC-5, AC-6 | Under which identity does each step run, and which grant does it hold that it never uses? |
| ID-12 | A credential is short-lived and scoped to its operation: a step's deadline never exceeds the credential's lifetime minus a grace period. | NIST SP 800-53 Rev. 5 IA-5, AC-6 | How long does each credential live against the step that uses it? |
| ID-13 | A rotation is one versioned, declared change; a first apply never changes a secret a running system uses. Verifiers accept the current and previous key until everything retained is re-signed. A static key has a stated maximum age. | NIST SP 800-53 Rev. 5 IA-5(1), SC-12 | How is each credential rotated, and what keeps working during it? |
| ID-14 | A design never relies on a permission nobody granted. A wider grant is an explicit owner decision, quoting the grant that exists and the grant needed; widening and narrowing a grant are separate changes. | NIST SP 800-53 Rev. 5 AC-2, AC-6 | Does the design rely on a permission nobody has granted? |
