# CF: Configuration and portability

Base catalog 1.1.0. Scope: no hardcoded setup, one record, class parity, zero remembrance, named boundaries. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| CF-01 | No tool, plan or test hardcodes one setup's host, user, path, IP, project or domain. Every per-setup value is read from the installation record or an existing code variable; one typed authority supplies URLs, ports and data paths. | Twelve-Factor App III, X | Which literal in the artifact would be wrong on another host, project, user or domain? |
| CF-02 | Every reader takes the record at the revision it renders; no render reads a live system. | Convention: renders read the committed record only | Does any render depend on live state? |
| CF-03 | A class difference (development, verification, production) is a declared record value or a provider binding per class, never a code fork. Development uses simulated providers through bindings; fixtures render only in development; a development security exception is explicit and unavailable in production. | Twelve-Factor App X | How does behaviour differ per class, and where is each difference declared? |
| CF-04 | Every class is installed by the same path, from code, on an empty machine; nothing is copied from another installation. | Twelve-Factor App X | Does any step work only because of state an older installation already has? |
| CF-05 | Zero remembrance: beyond the start command, nobody memorizes an endpoint, path, port, variable, generator command or setup sequence; the typed authority supplies them and startup shows them. | Convention: zero remembrance of setup | What must a person know or type that is not derived? |
| CF-06 | A fresh checkout works without a root `.env`. A missing external credential fails with an actionable diagnostic, never a placeholder secret. A value that needs a real-world measurement, rate or price and has none yet is one entry in a single placeholder list, allowed in the development class only; every other class refuses to render while any entry exists, and no such number is typed as a literal elsewhere. | Convention: fresh checkout needs no local files | What happens on a new machine with no local files? |
| CF-07 | Each tool has one authored configuration source; a generated artifact is a marked, reproducible projection of it and is never hand-edited. | Convention: one authored configuration source | Is any setting authored in two files? |
| CF-08 | Ports and hosts are named registry entries; no numeric port or raw host literal outside the registry. No new server, VM or port is introduced without a record entry. | Convention: named port and host registry | Which ports or addresses appear as literals? |
| CF-09 | An effect's memo covers its target's identity (instance id, registry endpoint, key fingerprint), so a replaced target re-runs the effect. | Convention: memo covers target identity | After the target is replaced, what makes each effect run again? |
| CF-10 | An immutable object's name covers every value substituted into it after the render. | Convention: immutable name covers substitutions | Can a substituted value change under an unchanged name? |
| CF-11 | One term per concept from the project's glossary, with units in names; event types are past-tense and versioned. | Domain-Driven Design (Evans): Ubiquitous Language | Does the artifact use two words for one thing, or a new word for an existing one? |
| CF-12 | No invented concept: no stage, environment, tier, account, term or parallel path the project owner did not ask for. The existing installations and adopted owners are used. | Convention: no invented concept | Which concept in the artifact has no approved source? |
| CF-13 | Times are UTC RFC 3339. Money and quotas are exact in the owner's unit and rounded only by the owner, one rounding authority per value. | RFC 3339 (timestamps); Convention: exact money, one rounding authority | Is any time local or any amount rounded by us? |
| CF-14 | A setup the design cannot serve is a named boundary, never silently assumed away. A boundary is recorded with the project owner's approval; the change that needs one cannot invent it. | Convention: unsupported setup is a named boundary | Which setups does the design not support, and where is each named? |
| CF-15 | No vendor name appears in the model; a registry, provider or cloud is a binding. | Hexagonal architecture (Cockburn): ports and adapters | Would another provider need a code change or only a binding? |
| CF-16 | A concurrent edit of one owner record is refused by the owner's conditional write (a revision check), never last-writer-wins. Where automation and operators both shape one record, each writes its own part and a field set in both is an error. | RFC 9110 §13.1.1 | What happens when two edits of one record race? |
| CF-17 | A DNS record is a declared resource applied by its release, and its reconciliation compares record against effect. | Convention: DNS record as declared resource | Who writes each DNS record, and what detects that the live record differs? |
| CF-18 | Every installation's values live in one versioned record under one schema. A missing required value fails validation with its path and expected type; no wizard, prompt or second copy supplies it. | Twelve-Factor App III (config separate from code); Convention: schema-validated configuration record | Where is each installation value recorded, and what fails when one is missing? |
| CF-19 | The record check and the render hold no credential and read no live state: a render is a pure function of the committed record, and the check refuses an invalid or over-entitled record before any effect. An exception is a step that consumes a secret an earlier effect creates, named in the design. | Convention: credential-free, deterministic check and render | Which read-only step holds a credential or reads live state? |
