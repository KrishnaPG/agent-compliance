# CF: Configuration and portability

Base catalog 1.0.0. Scope: no hardcoded setup, one record, class parity, zero remembrance, named boundaries. Each row is the whole rule; judge it from the row alone.

| ID | Rule | Provenance | Test question |
|---|---|---|---|
| CF-01 | No tool, plan or test hardcodes one setup's host, user, path, IP, project or domain. Every per-setup value is read from the installation record or an existing code variable; one typed authority supplies URLs, ports and data paths. | Twelve-Factor App III, X | Which literal in the artifact would be wrong on another host, project, user or domain? |
| CF-02 | Every reader takes the record at the revision it renders; no render reads a live system. | Twelve-Factor App III, X | Does any render depend on live state? |
| CF-03 | A class difference (development, verification, production) is a declared record value or a provider binding per class, never a code fork. Simulated providers and fixtures exist only in development; a development security exception is explicit and unavailable in production. | Twelve-Factor App X | How does behaviour differ per class, and where is each difference declared? |
| CF-04 | Every class is installed by the same path, from code, on an empty machine; nothing is copied from another installation. | Twelve-Factor App X | Does any step work only because of state an older installation already has? |
| CF-05 | Zero remembrance: beyond the start command, nobody memorizes an endpoint, path, port, variable, generator command or setup sequence; the typed authority supplies them and startup shows them. | Twelve-Factor App III, X | What must a person know or type that is not derived? |
| CF-06 | A fresh checkout works without a root `.env`. A missing external credential fails with an actionable diagnostic, never a placeholder secret. | Twelve-Factor App III, X | What happens on a new machine with no local files? |
| CF-07 | Each tool has one authored configuration source; a generated artifact is a marked, reproducible projection of it and is never hand-edited. | Twelve-Factor App III, X | Is any setting authored in two files? |
| CF-08 | Ports and hosts are named registry entries; no numeric port or raw host literal outside the registry. No new server, VM or port is introduced without a record entry. | Twelve-Factor App III, X | Which ports or addresses appear as literals? |
| CF-09 | An effect's memo covers its target's identity (instance id, registry endpoint, key fingerprint), so a replaced target re-runs the effect. | Twelve-Factor App III, X | After the target is replaced, what makes each effect run again? |
| CF-10 | An immutable object's name covers every value substituted into it after the render. | Twelve-Factor App III, X | Can a substituted value change under an unchanged name? |
| CF-11 | One term per concept from the project's glossary, with units in names; event types are past-tense and versioned. | Twelve-Factor App III, X | Does the artifact use two words for one thing, or a new word for an existing one? |
| CF-12 | No invented concept: no stage, environment, tier, account, term or parallel path the owner did not ask for. The existing installations and adopted owners are used. | Twelve-Factor App III, X | Which concept in the artifact has no approved source? |
| CF-13 | Times are UTC RFC 3339. Money and quotas are exact in the owner's unit and rounded only by the owner, one rounding authority per value. | Twelve-Factor App III, X | Is any time local or any amount rounded by us? |
| CF-14 | A setup the design cannot serve is a named boundary, never silently assumed away. A boundary is recorded with its owner and approval; the change that needs one cannot invent it. | Twelve-Factor App III, X | Which setups does the design not support, and where is each named? |
| CF-15 | No vendor name appears in the model; a registry, provider or cloud is a binding. | Twelve-Factor App III, X | Would another provider need a code change or only a binding? |
| CF-16 | A concurrent edit of one owner record is refused by the owner's conditional write (a revision check), never last-writer-wins. Where automation and operators both shape one record, each writes its own part and a field set in both is an error. | RFC 9110 §13.1.1 | What happens when two edits of one record race? |
| CF-17 | A DNS record is a declared resource applied by its release, and its reconciliation compares record against effect. | Twelve-Factor App III, X | Who writes each DNS record, and what detects that the live record differs? |
| CF-18 | Every installation's values live in one versioned record under one schema. A missing required value fails validation with its path and expected type; no wizard, prompt or second copy supplies it. | Twelve-Factor App III; infrastructure-as-code practice | Where is each installation value recorded, and what fails when one is missing? |
